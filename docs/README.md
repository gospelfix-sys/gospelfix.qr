## 쓰는 법

1. 화면·컴포넌트를 만들기 전에 `DESIGN.md`(또는 `design.shadcn.md`)를 AI에게 같이 준다. 세션이 바뀌면 AI는 이전 규칙을 기억하지 못한다.
2. 값이 어긋나면 **번호 파일(01~09)이 우선**이다. `design.shadcn.md`와 `CLAUDE.md`는 그에 맞춰 고친다.
3. 마음에 안 드는 결과가 나오면 `08-guidelines.md`의 DON'T에 한 줄 추가한다.
4. 새 색·굵기·간격·모서리가 필요하면 코드보다 **먼저 해당 번호 파일의 표에 추가**하고 이유를 적는다.

## 핵심 원칙

- **모든 UX/UI는 shadcn/ui 컴포넌트를 기반으로 만든다.** 설정은 루트 `components.json`, 컴포넌트 추가는 `npx shadcn@latest add <이름>`.
- 목록보다 금지가 잘 지켜진다. "쓰지 않는다"까지 명시한다.
- 개수를 지킨다: 색 7개, 글자 6단계, 굵기 2종, 간격 6단계, 모서리 2종.
- 이 화면은 돈과 계좌번호를 다룬다. 장식보다 **대조 가능성(오입금 방지)과 신뢰**가 우선이다.
- 외부 요청 금지: 폰트·이미지·분석 스크립트를 추가하지 않는다 (`CLAUDE.md`).

## 결정 이력

- (2026-11-23) 브랜드 사이트(https://xn--o39aj34ba393o94b.com/)와 통일하기 위해 베이지 중립색 + 주황 포인트(#FF5500, 주 버튼에만)를 채택하고 `--radius`를 1rem으로 올렸다. 이전 결정("포인트는 검정 하나, 주황 미사용")을 사용자가 뒤집은 것이다. 보조 글자 #6B6B66·주 버튼 글자 검정·포커스 링 #111111은 대비 기준(4.5:1) 때문에 사이트 값과 다르다(`02-colors.md`).
- 오류 표시는 빨간색 없이 검정으로 한다(문구 `font-semibold` + `role="alert"`, 필드 `aria-invalid` 시 `border-foreground` 2px. 2026-11-23 이후 `--primary`가 주황이라 `border-primary`는 쓰지 않는다). `--destructive`는 `globals.css`에 정의만 두고 화면에 쓰지 않는다.

- 송금 화면(`/pay`)의 `GuideSteps`·고지문은 그대로 유지한다. 금액 없는 링크에서도 "금액 확인"이 보이는 것은 알려진 사실이며 의도적으로 유지한다.
